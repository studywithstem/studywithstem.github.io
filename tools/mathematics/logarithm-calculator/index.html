FIELD NOTESLOG ARITHMETIC

  • The domain: arguments must be positive — log 0 and log(−x) have no real answer.
  • The base: any positive number except 1. Since 1ʸ = 1 always, base 1 has no inverse.
  • Change of base: logb x = ln x ÷ ln b — the identity this tool uses for every custom base, written out as it works.
  • Preset bases: e ≈ 2.71828 (natural), 10 (common), 2 (binary — doubling times, bits, octaves).
  • Inverse pair: blog_b x = x and logb(bʸ) = y — every answer here is checked by exponentiating back.
  • log 1 = 0 in every base — the one argument with a universal answer.
  • Exact powers are caught: log₂ 64 reads 6, never 5.9999999 — rational answers snap when x = bp/q.

03

Frequently asked questions

The questions students actually ask about logarithms — answered the way this tool works them out.

Q·01How do I calculate a logarithm without a calculator?
Rewrite it as an exponent question — logb(x) asks "b raised to what power gives x?" For log₂ 64, factor the argument: 64 = 2 · 2 · 2 · 2 · 2 · 2 = 26, so the answer is 6. When no exact power exists, fall back on the change-of-base formula, logb x = ln x ÷ ln b, and look up the two natural logs.
Q·02How do I solve a log equation with a missing value?
Convert to exponential form. log₃ x = 4 becomes x = 3⁴ = 81; logx 49 = 2 becomes x² = 49, so x = 7. The SOLVE tab fills the blank in any of the three positions — argument, base or value — and then checks the answer back by substitution.
Q·03What is the change-of-base formula and when do I use it?
logb(x) = ln(x) ÷ ln(b) — sometimes written with log₁₀ on top and bottom. It lets you evaluate a logarithm in any base using only natural or common logs, which is exactly how this tool computes custom bases; the substitution is written out in the work panel so you can copy it.
Q·04What is the difference between ln, log and log₂?
Only the base changes. ln is base e ≈ 2.71828, the natural logarithm used for growth, decay and calculus. log on its own means base 10, the common logarithm of the decimal system: log 1000 = 3. log₂ is base 2, the binary logarithm of doubling times, bits and octaves: log₂ 8 = 3. All three are one tap away in the tool.
Q·05What are the product, quotient and power laws of logarithms?
log(M·N) = log M + log N, log(M ÷ N) = log M − log N, and log(Mᵏ) = k·log M. Together they turn multiplication into addition — the property logarithms were invented for. The LOG LAWS tab expands all three with your own numbers and verifies each against the direct computation.
Q·06Why can't I take the log of zero or a negative number?
Because by is strictly positive whenever b > 0 — no exponent ever lands on 0 or below, so the inverse has nothing to return. Real logarithms are defined for positive arguments only; log(−5) exists only in complex numbers, and even there it is multi-valued.
Q·07Why is a base of 1 not allowed?
1y = 1 for every possible y. The exponential collapses everything to the same output, so it is not one-to-one and cannot be inverted — there is no log base 1. The same argument rules out b ≤ 0. A valid base is any positive number other than 1.
Q·08What is an antilog, and how do I compute it?
The antilog is exponentiation — the inverse of taking a logarithm. If logb(x) = y, then antilogb(y) = by = x. To compute one here, open the SOLVE tab and leave the argument box empty: log₃ x = 4 returns x = 81, which is antilog₃ 4.
Q·09Is it free, and does my input leave the page?
Completely free — no sign-up, no locked features, no limits. All arithmetic runs locally in your browser; nothing is recorded or transmitted, and the page keeps working offline once it has loaded.
